# 智能图表决策流程详解

## 图表类型识别

### 业务流程图
**关键词**：流程、步骤、决策、分支、条件
**特征**：描述业务操作或处理流程

### 时序图
**关键词**：交互、调用、时序、序列、请求、响应
**特征**：描述系统组件之间的交互顺序

### 数据流图
**关键词**：数据流、输入、输出、处理
**特征**：描述数据在系统中的流动

### 系统架构图
**关键词**：架构、组件、模块、部署、服务
**特征**：描述系统的组件结构和关系

### 原型图
**关键词**：界面、页面、UI、原型、布局
**特征**：描述用户界面的布局和元素

## 复杂度评估

### 低复杂度
- 元素数量：≤ 5个
- 关系复杂度：简单，一对多关系为主
- 层次深度：≤ 2层

### 中复杂度
- 元素数量：6-15个
- 关系复杂度：中等，包含多对多关系
- 层次深度：3-4层

### 高复杂度
- 元素数量：> 15个
- 关系复杂度：复杂，包含循环、条件分支
- 层次深度：> 4层

## 实现方式决策

### 决策矩阵

| 图表类型 | 低复杂度 | 中复杂度 | 高复杂度 |
|---------|---------|---------|---------|
| 业务流程图 | Mermaid | Mermaid | Mermaid |
| 时序图 | Mermaid | Mermaid | Mermaid |
| 数据流图 | Mermaid | Mermaid | Mermaid |
| 系统架构图 | Mermaid | Mermaid | Coze 生图 + Mermaid |
| 原型图 | Coze 生图 + Mermaid | Coze 生图 + Mermaid | Coze 生图 + Mermaid |

### 决策逻辑

1. **识别图表类型**
   - 根据关键词和特征判断图表类型

2. **评估复杂度**
   - 统计元素数量
   - 分析关系复杂度
   - 评估层次深度

3. **选择实现方式**
   - 根据决策矩阵选择
   - 业务流程图、时序图、数据流图 → 始终 Mermaid
   - 系统架构图 → 低/中复杂度 Mermaid，高复杂度 Coze 生图 + Mermaid
   - 原型图 → 始终 Coze 生图 + Mermaid

## 执行流程

### 场景A：仅 Mermaid

1. 根据图表类型生成 Mermaid 代码
2. 嵌入到文档中

### 场景B：Coze 生图 + Mermaid

**注意事项**：
- 对于系统架构图，特别是中高复杂度场景，必须使用信息保障约束
- 详细的三原则和Prompt模板见：[diagram-prompt-guide.md#系统架构图coze生图信息保障约束](diagram-prompt-guide.md#系统架构图coze生图信息保障约束)

**执行步骤**：
1. 生成 Mermaid 代码（信息保障）
2. 生成图像描述 prompt
3. **应用信息保障约束**（见 diagram-prompt-guide.md）
4. 调用 Coze 生图能力
5. 获取图片链接
6. 将图片和 Mermaid 代码同时嵌入到文档中

## 复杂度评估示例

### 示例1：低复杂度（业务流程图）
```
需求：用户登录流程
元素：用户、登录、验证、首页（4个）
关系：线性流程
层次：单层
决策：Mermaid
```

### 示例2：中复杂度（系统架构图）
```
需求：电商系统架构
元素：前端、网关、用户服务、订单服务、支付服务、数据库、缓存（7个）
关系：前端→网关→服务→数据库
层次：3层（前端层、网关层、服务层、数据层）
决策：Mermaid
```

### 示例3：高复杂度（系统架构图）
```
需求：大型电商系统微服务架构
元素：20+ 个服务、网关、数据库集群、缓存集群、消息队列、监控系统等
关系：服务间调用、数据库分片、缓存策略、异步消息、监控告警
层次：5+ 层（前端层、网关层、服务层、数据层、基础设施层）
决策：Coze 生图 + Mermaid
```

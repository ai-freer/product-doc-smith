# product-doc-smith

`product-doc-smith` 是一个面向产品文档生成场景的 Skill，核心目标是：

- 识别用户输入所处的产品阶段（探索 / 方案 / 实现 / 演进）
- 匹配合适的文档框架（本地 22 个模板 + 通用框架）
- 在信息不足时通过交互式提问逐步补全内容
- 在持续修改时做阶段一致性检查，必要时引导新文档创建

该项目适用于 PRD、技术设计、竞品分析、用户研究、测试计划、API 文档等输出场景。

## 核心能力

- 内容充足度判断：按字数、信息点、结构化程度分为 4 档
- 文档框架匹配：从 `references/templates/` 选择最合适模板
- 智能填充与标注：缺失项使用 `[待补充]` / `[TODO]`
- 标准动作执行：外部参考检查、产品类型识别、专用章节选取
- 质量检查：全文读、去重、细节度控制、标注准确性检查
- 持续修改机制：支持阶段前进判断与文档拆分建议

## 流程概览

| 档位 | 判断标准 | 流程 | 互动程度 |
| --- | --- | --- | --- |
| 详尽 | >500 字、>5 信息点、结构完整 | A 直接填充 | 几乎不互动 |
| 充足 | 300-500 字、3-5 信息点、结构化 | B 关键确认式填充 | 关键确认 |
| 一般 | 100-300 字、1-2 信息点、部分结构 | C 部分交互式引导 | 部分引导 |
| 不足 | <100 字、<2 信息点、无结构 | D 完整交互式引导 | 完整引导 |

此外支持：

- E 持续修改与完善（用户提出修改意见时）
- 可视化图表生成（Mermaid / Coze 生图 + Mermaid）

## 使用方式

1. 在支持 Skill 的智能体环境中加载 `SKILL.md`。
2. 将用户输入（想法、草稿、现有文档）交给智能体。
3. 智能体按充足度自动选择流程 A/B/C/D，或在修改场景走流程 E。
4. 生成文档后执行 `final-check` 相关检查，再输出最终 Markdown。

## 推荐输入示例

- 详尽输入：完整 PRD 草稿（可直接结构化输出）
- 充足输入：目标 + 核心功能 + 范围 + 技术选型（关键确认后输出）
- 简短输入：一句想法（通过交互提问逐步生成完整文档）

## 质量与约束

- 避免 AI 化表达，保持具体业务语境
- 不编造数据；缺失内容应明确标注待补充
- 尊重用户指定模板、章节跳过与阶段选择
- 仅在需要时读取参考资料，控制上下文冗余

## 维护建议

- 新增模板时，同时更新：
  - `references/templates/`
  - `references/word-templates-guide.md`
  - `SKILL.md` 中相关说明
- 调整流程规则时，保持 `SKILL.md` 与 `references/*` 一致，避免引用漂移。
